# CRC transport and external signing adapters

`@crclaunch/crc20-adapters` serializes plans produced by the authoritative `@crclaunch/crc20-protocol` package. It does not calculate economics, choose change, implement alternate protocol rules or receive wallet private keys. Built Node and browser exports share the same API. The browser build supplies a lexical Buffer binding to bitcoinjs dependencies without setting browser globals.

Use `preparePlanSigning(plan, options)` to map exact inputs/outputs into a version-2 PSBT. Each input must have an assigned wallet account or an already finalized external witness. Wallet address/public-key ownership and nested redeem programs are proven before a request. Core purchase witnesses survive unchanged; finalized Guardian signatures are verified by the same core before the buyer prompt. Wallet inputs use ALL and only the specified indexes are requested, with broadcast disabled.

`prepareOfferSigning(terms, account)` prepares the exact core seller input-0/output-0 request with sighash 0x83. `requestOfferSigning(provider, prepared)` requests canonical BIP322 terms, checks fresh network metadata again, then requests the seller PSBT. `completeOfferSigning` decodes the measured base64 witness framing and calls the core's authorization verifier. Cancellation is typed REJECTED; unsupported/mismatched network is NETWORK. No fallback or automatic retry exists.

`completePlanSigning(prepared, response, ledger?)` rejects changed unsigned transaction bytes, witness prevout amounts/scripts and protected finalized/redeem/internal-key data. It finalizes only wallet inputs, enforces the requested flag and passes the extracted transaction and original prevouts through `validateFinalTransaction`. Supply the current ledger to validate protocol allocation rules as well as transaction intent. Prepared contexts must originate from trusted core plans; do not accept client-supplied contexts as authorization. Live UTXO/chain observations, HTTP, persistence and broadcasting remain the callers' responsibilities.

The core's `encodeProtocolDto`/`decodeProtocolDto` preserve canonical decimal-string amounts through JSON, including bigint atom amounts above the safe-integer range. They are transport codecs, not domain validators; consumer trust boundaries still require the core's config, state, offer and signature validation.

Tests reconstruct native, nested and Taproot PSBT requests and final transactions from actual Xverse 2.9.3 evidence, reject tampered data and network changes between prompts, and execute the package in real Chromium. An additional actual Xverse signing response completes a core mint plan with a finalized test Guardian script-path witness and nested buyer ALL signature. All inputs are synthetic and the wallet was unfunded; no transaction was broadcast. This does not prove production recovery custody, live-chain execution or mobile support.
