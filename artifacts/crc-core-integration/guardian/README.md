# Shared-core Guardian evidence

Guardian now uses the authoritative core transition for wallet-first preflight,
then the same complete-signature verifier after custody signing. The narrow
preflight exception permits only an unsigned vault input 0. Every wallet input
must already authorize the exact transaction. Request state, fee arithmetic,
asset amounts and custody metadata cannot replace trusted registration/state.

`mined-guardian.json` records actual mint, sell and inventory-buy transactions,
core plans, indexed assets and allocations. Each uses exactly 1,000 sats miner
fee. Tests compare indexed assets/allocations directly with core predictions,
verify complete signatures, and mine through Bitcoin Core 30.0. All mutable
Bitcoin/PostgreSQL resources are disposable test-owned containers. Keys are
public fixtures; no user funds or public network were used.

Five service tests cover malformed requests, all three trades, journal
idempotence, fee/successor/wallet/recovery/stale-vault rejection before custody,
actual reorg restoration and cached-signature reuse, and a state change during
signing that releases the failed claim before a successful mined retry. Journal
lease/CAS and stale-root checks also run in the real PostgreSQL indexer suite.
The fixed-key test funding selector has a failing-first regression for generated
wallet change addresses.

Logs preserve failing-first core, adapter, journal and service tests; final gates
include 140 core tests plus the additional funding regression, 14 adapter tests,
89 indexer tests (one unrelated database suite skipped), five Guardian service
tests, and workspace typecheck/lint/build. Standalone Guardian passes install,
Rust build, package builds, typecheck, lint and 30 tests (14 existing environment
dependent tests skipped). Its Docker image also imports the packaged shared
service and rejects malformed requests with networking disabled. Nested compiler
cache files are excluded from Docker so clean images emit package JavaScript.

Standalone runtime sources are generated by
`scripts/guardian/sync-crc-core.py`; `--check` compares 37 managed files with
the canonical source. The manifest records hashes. Only package/test metadata
and the core's relative tsconfig path adapt to the standalone workspace.
The database suffix/migrations share canonical definitions while preserving
unrelated infrastructure. Old standalone CRC validators were deleted. The
preexisting user README edit was preserved.

The custody model remains an operator-controlled execution key with configured
delayed recovery; Bitcoin enforces signatures and the core enforces CRC rules.
Native, nested and Taproot wallet adapter evidence remains in the earlier wallet
milestone. The mined service fixture uses native wallet funding and a genuine
Guardian Taproot path with the configured recovery branch. No production custody,
replacement deployment, application reset, frontend E2E or live-wallet canary is
claimed. Wallet-first API/browser preparation remains the next integration gate.
