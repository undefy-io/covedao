# RPC genesis verification

Beads `covedao-ko7`, deployed2026-10-04. Frontend identity verification uses the configured public RPC's `getblockchaininfo` and `getblockhash(0)`, comparing genesis against the configured network's expected hash from [Bitcoin Core v30.0 chain parameters](https://github.com/bitcoin/bitcoin/blob/v30.0/src/kernel/chainparams.cpp). It no longer calls Esplora `/block-height/0`. Wallet-address UTXO discovery still uses the configured address index; proof verification, current input checks, and broadcasting work when that index is unavailable.

Twelve targeted public-chain and real Chromium desktop/mobile tests pass, covering wrong network/genesis, index outage, direct review, exact-byte broadcasting, and recovery. Web typecheck/lint and the production Signet build pass. The built image's public-chain source hash matches the workspace. `public-browser-probe.json` records five actual read-only browser requests, with zero genesis-index requests and zero backend wallet discovery. No user wallet signatures or valid broadcasts were initiated.

The existing Signet web/worker images were updated without migrations, bootstrap, or reset. `deployment.json` verifies the17 prior sessions' saved contents and8 prior events were retained; one pending transaction confirmed naturally while verification ran, causing its READY session to become BROADCAST and the event count to reach9. Registrations/profile remain unchanged. A temporary verification database restored the pre-upgrade backup to compare session/event contents, and was removed. Backup/profile live under `.local/signet-backups/rpc-genesis-ko7/`; rollback image tags are `covedao-rpc-genesis-rollback:{web,worker}`.
